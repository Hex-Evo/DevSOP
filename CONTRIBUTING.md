# Contributing to DevSOP

DevSOP is maintained by Hex-Evo. We welcome community input and carefully review all contributions.

## What We Accept

- **Bug reports:** If DevSOP's audit checks produce false positives, miss a common pattern, or break on a specific stack, open an issue with the details.
- **Stack-specific gaps:** If your language, framework, or toolchain is not covered by the audit protocol, open an issue describing what checks should exist.
- **Documentation improvements:** Typos, unclear wording, better examples.
- **Bug fixes:** Pull requests that fix identified issues.

## What We Do Not Accept

- **Core architecture changes.** The audit/onboard/task-list structure is intentional. PRs that restructure the framework will be closed.
- **AI-tool-specific logic.** DevSOP is agent-agnostic by design. PRs that add model-specific syntax, tool-specific formatting, or vendor-locked features will be closed.
- **Feature additions without an issue first.** Open an issue, discuss the addition, get confirmation before building.

## How to Contribute

1. Open an issue describing the bug, gap, or improvement.
2. Wait for confirmation from a maintainer before submitting a PR.
3. Keep PRs focused. One fix or addition per PR.
4. Test your changes against at least one real project before submitting.

## Code of Conduct

Be constructive. Be specific. Be respectful. That covers it.
